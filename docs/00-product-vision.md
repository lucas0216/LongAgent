# 00 · 产品愿景

## 一句话定位

**给小白的 AI 桌面助手——不只能聊天，还能动你的文件。**

## 我们为什么做这件事

### 当前 AI 用户的真实痛点

国内 2-3 亿人在用 ChatGPT/豆包/元宝/通义/文心一言这类对话型 AI。他们享受到了"AI 帮我想"的便利，但卡在一个共同的痛点上：

> **每次都要复制粘贴文本进进出出。** AI 不能直接动我的文件、不能保存产物、不能批量处理、用完就没了。

这种割裂体验让 AI 的实际生产力**远低于它的理论上限**。

### 现有产品没解决这个问题

| 产品类型 | 代表 | 为什么不行 |
|---|---|---|
| 对话型 AI | ChatGPT / 豆包 / 元宝 / 通义 | 没有本地文件能力，仍然要复制粘贴 |
| AI 客户端 | Cherry Studio / ChatBox | BYOK 配置门槛劝退小白，且仍是 chat-first |
| OS 级 AI 助手 | Marvis / Claude Computer Use | 重、慢、要求 16GB+ 内存、信任飞跃太大 |
| 开发者 Agent | Claude Code / Cursor / Aider | 需要懂代码/CLI，小白完全用不了 |

## 我们要建的是什么

一个**桌面应用**，让用户在熟悉的"和 AI 聊天"体验之上，获得**真正能动文件的 Agent 能力**——

- 拖一个 PDF 进来 → AI 读完直接生成摘要 .docx 保存到桌面
- 把一文件夹截图丢进来 → AI 按内容分类好，重命名
- 一句"做一份本月报销汇总" → AI 读 Excel、整理、生成新表

而所有这一切，**用户无需配 API Key、无需懂"什么是 Agent"、无需付费即可上手**。

## 心智模型

### Task-first 而非 Chat-first

| 维度 | Chat-first（ChatGPT 范式） | Task-first（我们的范式） |
|---|---|---|
| 首屏 | 对话框等输入 | "你今天想做什么"场景卡片 |
| 主交互 | 打字 | 拖文件 + 自然语言任务 |
| 产物 | 对话历史 | 实际文件（docx/xlsx/png）|
| 衡量价值 | 回答好不好 | 任务完成没完成 |

### 三个核心原则

1. **本地优先**：默认模型在本地跑，文件不出电脑，断网可用
2. **透明可控**：Agent 每一步可见，可中断、可撤销、可重做
3. **零配置上手**：不要让小白学"什么是 API Key"

## 我们坚决不做什么（避免膨胀）

### MVP 阶段明确不做

- ❌ **多模型聊天客户端的形态**（避免和 Cherry Studio / ChatBox 撞车）
- ❌ **浏览器自动化 / Computer Use**（v1.5 再做，理由见 ADR-0006）
- ❌ **屏幕理解 / OS 级集成**（Marvis 主场，且体验都未达可用）
- ❌ **多 Agent 编排框架**（不暴露 Agent 概念给小白）
- ❌ **App 控制 / 系统设置自动化**（信任飞跃太大）
- ❌ **绘图 / 视频 / 音频生成**（不在文件场景核心）
- ❌ **跨设备同步**（云服务非必需）

### 永远不做

- ❌ **替用户做不可逆决策**（删文件、发消息、转账）—— 这是产品价值观
- ❌ **未经用户明确授权读取整盘文件**（隐私优先）
- ❌ **训练用户数据**（数据不出端，不能上云训练）

## 为什么这件事现在有窗口

1. **模型成本陡降**：DeepSeek V4 Pro 永久降到 ¥0.025/M（缓存命中），单用户月成本可控
2. **本地小模型够用**：Qwen3-4B 在中文文档场景已经够小白用
3. **Tauri 2.0 成熟**：包小、内存低、Mac/Win 双端有腾讯元宝实证
4. **小白 AI 用户已养成**：豆包/元宝把"用 AI"教育做完了，他们已经在找下一步
5. **大厂还没做对**：Marvis 的"OS 级"路线笨重、错率高，给了细分玩家窗口

## 成功的样子（北极星指标）

| 阶段 | 指标 | 目标 |
|---|---|---|
| MVP 上线 | 90 秒内 Aha Moment 达成率 | > 60% |
| 月 1-3 | DAU/MAU | > 25% |
| 月 3-6 | L1 → L2 付费转化率 | > 3% |
| 月 6-12 | NPS | > 40 |
| 长期 | 用户口中描述本产品时的关键词 | "动文件"、"省事"、"不用复制粘贴" |
