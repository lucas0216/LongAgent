# 07 · 模型路由与成本优化

## 核心目标

在保证用户体验的前提下，**让 L1 单用户月成本控制在 ¥1 以内**，让产品在 1-10 万 MAU 规模下仍能由付费转化覆盖成本。

## 三个模型层

| 层 | 模型 | 用途 | 单次成本（典型）|
|---|---|---|---|
| 本地 | Qwen3-4B Q4 / 1.7B Q4 | 翻译、总结、改名、分类 | ¥0（电费忽略）|
| 云端 Flash | DeepSeek V4 Flash | 普通对话、规划 | ~¥0.0036 |
| 云端 Pro | DeepSeek V4 Pro | 复杂推理、长上下文 | ~¥0.0085 |

## 路由决策流程

```
                       用户输入
                          │
                          ▼
              ┌─────────────────────────┐
              │  规则前置过滤            │
              ├─────────────────────────┤
              │  1. 是否敏感词? → local │
              │  2. 是否隐私模式? → local│
              │  3. 是否离线? → local   │
              │  4. 配额耗尽? → local   │
              └───────┬─────────────────┘
                      │ 都不命中
                      ▼
            ┌─────────────────────┐
            │  意图分类器          │
            │  本地 Qwen3-0.6B    │
            │  输出: 任务类型 + 复杂度│
            └─────────┬───────────┘
                      ▼
            ┌─────────────────────┐
            │  按复杂度路由        │
            ├─────────────────────┤
            │ < 0.3  → local      │
            │ 0.3-0.7 → flash     │
            │ > 0.7  → pro        │
            └─────────┬───────────┘

            ┌─────────────────────┐
            │ Provider 健康检查    │
            │  - 火山方舟优先      │
            │  - 失败切 DeepSeek   │
            │  - 再失败切本地      │
            └─────────────────────┘
```

## 敏感词触发本地

匹配以下词时**强制本地**（不询问用户）：
- 身份证、护照
- 银行卡号、信用卡
- 工资、薪资
- 合同（仅在文件名）
- 病历、诊断
- 家庭住址（精确格式如 "X 市 X 区 X 路 X 号"）

实现策略：
- 用户输入和文件名先过滤
- 文件内容**不扫描敏感词**（隐私优先）
- 用户可以在设置里添加/删除敏感词

## 成本控制的 5 个 Lever

### Lever 1：System Prompt 前缀缓存（最大）

**目标**：缓存命中率 > 70%（生产环境）

**实现要求**：
- System prompt **绝对稳定**，包括：
  - 工具描述（~2000 tokens）
  - 行为指令（~800 tokens）
  - Few-shot 示例（~500 tokens）
- **不要**根据用户/任务动态裁剪
- **不要**改标点、空格、换行
- 用户偏好等动态内容放在 system 之后

**成本对比**：
- 不优化：3 元/M（cache miss）
- 优化后：0.025 元/M（cache hit）
- **降幅 99%**

**监控**：每次调用记录 `tokens_input_cached` / `tokens_input`，命中率低于 60% 报警。

### Lever 2：分级路由

**目标**：Flash 占比 > 70%

**策略**：
- 默认走 Flash（不是 Pro）
- 仅在意图分类器判定"复杂推理 + 长上下文"才升 Pro
- 错误回退：Flash 失败再升级到 Pro（不是反之）

**成本对比**：
- 全 Pro：单 MAU/月 ¥2.0
- 70% Flash + 30% Pro：单 MAU/月 ¥0.68

### Lever 3：本地模型兜底高频小任务

**目标**：本地承担 30% 以上的"用户感知调用"

**适合本地的任务**：
- 文件名生成
- 短翻译
- 关键词提取
- 简单回复（"好的"、"明白了"）
- 意图分类（这部分必然本地）

**实现要求**：
- 这些任务**不走 Agent loop**（直接调本地模型，省去 plan/execute 开销）
- 用户感知无差异

### Lever 4：上下文裁剪与摘要

**目标**：单次调用 input < 6000 tokens

**策略**：
- 对话历史超过 5 轮自动摘要（用本地模型做）
- 文件内容超过 5000 tokens 截断或分块
- 工具结果超过 1000 tokens 截断（保留前 500 + 后 500）
- RAG 检索返回 top 3，不返回 top 10

**风险**：复杂任务可能需要更长上下文，要监控失败率，必要时按任务调整阈值。

### Lever 5：硬性配额

**L1 用户**：
- 每天 20 次云端调用上限
- 单次任务最多触发 5 次模型调用
- 超出**自动降级到本地**，不阻塞用户

**计算逻辑**：
- 一个"模型调用" = 一次 LLM API 请求
- 一个"用户请求"可能触发多次模型调用（Agent loop）
- 配额按"模型调用"计数

## 单次调用成本计算

### 典型 prompt 结构

| 部分 | tokens | 缓存命中？ |
|---|---|---|
| System prompt | 3000 | ✅ 99% |
| 用户偏好 | 200 | ✅ 90% |
| 历史摘要 | 500 | 半（70%）|
| 最近 3 轮对话 | 800 | 部分（30%）|
| 当前用户输入 | 150 | ❌ |
| 文件/工具内容 | 1500 | ❌ |
| **输入总计** | **6150** | |
| **输出** | 400 | — |

### 缓存命中率 70% 时

**V4 Pro 单次**：
- 命中输入：4300 × ¥0.025/M = ¥0.0001
- 未命中：1850 × ¥3/M = ¥0.0056
- 输出：400 × ¥6/M = ¥0.0024
- **合计：≈ ¥0.0081**

**V4 Flash 单次**：
- 命中输入：4300 × ¥0.2/M = ¥0.0009
- 未命中：1850 × ¥1/M = ¥0.0019
- 输出：400 × ¥2/M = ¥0.0008
- **合计：≈ ¥0.0036**

## 用户/MAU 月成本估算

### 假设

- DAU/MAU = 30%
- DAU 平均每天 7.35 次用户请求（重度/中度/轻度加权）
- 每次用户请求 ≈ 2 次模型调用
- 70% Flash / 30% Pro
- 缓存命中率 70%

### 计算

| 项目 | 调用数/MAU/月 | 单价 | 月成本 |
|---|---|---|---|
| Flash 调用 | 135 × 70% = 94 | ¥0.0036 | ¥0.34 |
| Pro 调用 | 135 × 30% = 41 | ¥0.0081 | ¥0.33 |
| **合计** | **135** | | **≈ ¥0.67** |

## 收支平衡条件

L2 订阅 ¥29/月时，需要的转化率：

| MAU | 月成本 | 需付费用户 | **需转化率** |
|---|---|---|---|
| 10,000 | ¥6,700 | 231 | **2.31%** |
| 100,000 | ¥6.7万 | 2,310 | **2.31%** |

**行业参考**：C 端工具 freemium 转化率 3-8%（Bear, PicGo, Eagle 等）

**结论**：只要 3% 转化即可健康运转。

## 监控与告警

### 实时指标

每个用户每天上报（匿名）：
- 调用次数（按模型）
- 缓存命中率
- 平均延迟
- 错误率

### 告警阈值

| 指标 | 阈值 | 行动 |
|---|---|---|
| 全局缓存命中率 | < 60% | 检查 system prompt 是否变动 |
| 单用户日成本 | > ¥3 | 限流 + 标记 |
| Pro 调用占比 | > 40% | 路由器调优 |
| 错误率 | > 5% | 切换 provider |
| 单用户错误率 | > 30% | 标记 + 邮件支持 |

## 异常用户处理

### 滥用检测

- 单用户日调用 > 200 次 → 限流 + 邮件确认
- 调用模式高度规律（疑似脚本）→ 加 captcha
- 短时间高频文件操作 → 提示

### 处理流程

```
触发阈值
   ↓
临时限流（降级到本地）
   ↓
邮件确认是否合理使用
   ↓
不回应 → 永久降级到本地
回应是误判 → 解除限流，调高阈值
```

## v1.0 之后的优化方向

| 方向 | 预期收益 |
|---|---|
| 训练自己的路由器（替代规则）| 准确率 +5-10%，成本 -10% |
| 引入更便宜的本地模型推理引擎（如 vLLM）| 本地比例 +10% |
| Cache 层加入语义匹配（不只是前缀）| 命中率 +5% |
| 单次任务超时熔断 | 异常成本 -50% |
| 批量调用合并（同种类操作）| 调用数 -30% |
