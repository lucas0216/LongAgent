# 09 · 开发路线图

## 总览

```
M0: 启动准备 (1 周) ────┐
M1: 核心骨架  ────┐    │
M2: Aha 功能 ────┤    │
M3: 闭环      ────┤────┴── MVP v1.0 上线 (Windows)
M4: 打磨上线 ────┘
                          │
                          ▼
v1.1 (+1月): 知识库 + 任务管理
                          │
                          ▼
v1.5 (+3月): Mac 版 + 白名单 browser use
                          │
                          ▼
v2.0 (+6月): 企业版 / 垂直版（视市场）
```

## M0 · 启动准备（第 0 周）

**目标**：把基础设施搭起来，避免后面卡。

### 任务

- [ ] 注册 Apple Developer ($99/年) — 即便 MVP 不发 Mac，CI 也要用
- [ ] 注册 Windows 代码签名证书（标准证书 ¥1500/年）
- [ ] 申请火山方舟 API + 实名（生产用）
- [ ] 申请 DeepSeek 官方 API（备用）
- [ ] 选购域名（暂定 longagent.app 或 longagent.cn）
- [ ] 注册微信支付商户号（要营业执照）
- [ ] 注册支付宝商户号
- [ ] CI/CD 设置（GitHub Actions: Win runner + macOS runner）
- [ ] Sentry / 类似崩溃上报服务
- [ ] 内部 Slack / 飞书工作群

### 产出

- 完整的开发环境
- 所有需要预先申请的资质和账户就位

### 风险

- 商户号申请可能要 2-4 周（预留时间）
- 苹果开发者审核也要 1-2 周

## M1 · 核心骨架（第 1-4 周）

**目标**：跑通最小可行管线（端到端 demo），验证技术选型。

### Sprint 1.1 · Tauri + Python sidecar 通信（第 1 周）

- [ ] 初始化 Tauri 2.0 项目
- [ ] 集成 Python sidecar (FastAPI + uvicorn)
- [ ] 实现 Sidecar 进程生命周期管理（Rust 侧）
- [ ] UI 调 Tauri → Tauri 调 Python → 返回 → UI 显示
- [ ] **里程碑**：HelloWorld 端到端跑通双端（Win + Mac）

### Sprint 1.2 · Ollama 集成 + 本地模型（第 2 周）

- [ ] 嵌入 Ollama runtime（用 sidecar 子进程）
- [ ] 首次启动下载 Qwen3-4B（带进度 UI）
- [ ] 跑通本地聊天接口
- [ ] 跑通本地嵌入接口（BGE-M3）
- [ ] **里程碑**：本地模型完整可用

### Sprint 1.3 · 云端 API + 路由（第 3 周）

- [ ] 实现 LLM Provider 抽象（OpenAI 兼容）
- [ ] 接入火山方舟 + DeepSeek 官方
- [ ] 实现多供应商 fallback
- [ ] 实现 **System prompt 前缀稳定 + 缓存验证**（最关键）
- [ ] 实现规则路由（local/flash/pro）
- [ ] **里程碑**：缓存命中率 > 70% 实测验证

### Sprint 1.4 · 第一个端到端 Demo（第 4 周）

- [ ] PDF 解析工具（pdfplumber）
- [ ] DOCX 生成工具
- [ ] 实现最简 Agent Loop（plan → tool → final）
- [ ] 实现执行流 SSE 协议
- [ ] UI 展示执行流（极简版）
- [ ] **里程碑**：「拖 PDF → 生成摘要 DOCX」完整 demo 跑通

### M1 完成判据

✅ 一个真实用户能在双端拖 PDF 进来，看见执行流，得到摘要 DOCX，整个过程 < 60 秒。

## M2 · Aha Moment 功能（第 5-8 周）

**目标**：把 demo 变成"用户看了愿意留下来"的体验。

### Sprint 2.1 · 拖拽与首页（第 5 周）

- [ ] 文件浮层 UI（缩略图 + AI 建议）

- [ ] 每个场景的 prompt 模板 + 引导
- [ ] "试一下示例" 内置 demo 文件

### Sprint 2.2 · 文件解析全家桶（第 6 周）

- [ ] DOCX 解析 + 生成
- [ ] XLSX 解析 + 生成
- [ ] PPTX 解析（生成留 P1）
- [ ] 图片 OCR（RapidOCR）
- [ ] TXT / MD
- [ ] 错误处理与降级

### Sprint 2.3 · 执行流可视化打磨（第 7 周）

- [ ] 执行流组件设计稿落地
- [ ] 步骤图标系统（📖✏️🧠✅❌）
- [ ] 流式动画
- [ ] 步骤详情展开
- [ ] 暂停 / 中断按钮
- [ ] 任务标题自动命名

### Sprint 2.4 · 撤销 + 产物管理（第 8 周）

- [ ] 文件操作快照系统
- [ ] 撤销按钮 + 确认弹窗
- [ ] 产物卡片 UI
- [ ] 默认产物目录管理
- [ ] 一键打开文件 / 文件夹
- [ ] **里程碑**：完整的"拖入 → 执行 → 产物 → 撤销"闭环

### M2 完成判据

✅ 内部 5 个测试用户跑完 Onboarding 后，90 秒内完成首个任务并触发 Aha Moment 的比率 > 60%。

## 风险缓冲

| 风险 | 缓冲安排 |
|---|---|
| 关键技术 PoC 失败 | M0-M1 第一周强制做技术验证（Tauri + Python + Ollama 双端跑通）|
| 模型成本超预算 | 缓存命中率监控前置到 M1 |
| 用户访谈不积极 | M0 就开始招募 |
| 团队能力差距 | 关键里程碑前留 20% buffer |
| 上游 API 变化 | 多供应商架构从 M1 就准备 |

## 团队配置建议

### 最小可行团队（1-2 人）

| 角色 | 工作量 |
|---|---|
| 全栈（前端 + Rust + Python）| 1 人，全职 |
| 设计/PM（兼）| 0.5 人 |

### 理想 MVP 团队（3-4 人）

| 角色 | 工作量 |
|---|---|
| 前端（React + Tauri UI）| 1 人 |
| 后端（Rust + Python）| 1 人 |
| 产品 / 设计 | 1 人 |
| 增长 / 运营 | 0.5-1 人（M3 起） |

## 关键节点回顾时间表

| 时间 | 回顾内容 | 调整 |
|---|---|---|
| M0 末 | 技术 PoC 是否成功 | 如失败，考虑 Electron / 调整选型 |
| M1 末 | 缓存命中率是否达 70% | 如不达，重审 prompt 设计 |
| M2 末 | Aha Moment 是否成立 | 如不成立，回到产品设计 |
| M3 末 | 性能 / 稳定性 | 调整 v1.0 范围 |
| M4 末 | 用户反馈 | 决定 v1.1 重点 |
