# 10 · 风险登记

## 风险等级定义

| 等级 | 含义 |
|---|---|
| 🔴 高 | 可能导致项目失败或重大延期 |
| 🟡 中 | 影响交付质量或时间 |
| 🟢 低 | 可控影响，需关注 |

## 产品风险

### P-01 🔴 小白用户找不到产品

**描述**：目标用户不会主动搜索新工具，获客成本可能远超预期。

**指标**：CAC > ¥50/用户即危险。

**缓解**：
- 内容营销前置（M0 就开始做账号）
- 抓 ChatGPT / 豆包 桌面用户的转化窗口
- 一切设计围绕"可分享的 Aha Moment"

**应急**：如果 M5 还没找到有效获客渠道，考虑接入既有平台（如做成微信小程序版的引流入口）。

### P-02 🔴 Aha Moment 不成立

**描述**：用户试用后觉得"和 ChatGPT 也差不多"，没有惊喜感。

**指标**：90 秒达成率 < 40%。

**缓解**：
- M2 末就找真实用户测试
- 每个 P0 功能必须能用 30 秒视频展示出差异
- 首页 4-6 个场景卡片做到一打开就有冲击

**应急**：如果真实小白觉得不够"哇"，重新设计首屏交互，可能需要更激进的产品形态。

### P-03 🟡 用户付费意愿低

**描述**：L1 → L2 转化率不达 3%。

**缓解**：
- 配额设计触发"想要更多"的体验（不能太抠也不能太松）
- 付费墙时机不要太早或太晚（详见 [04-user-flows](04-user-flows.md)）
- 价格 A/B 测试

**应急**：如转化低，转向 L3 BYOK 为主（但要承担定位偏移）。

### P-04 🟡 与豆包/元宝桌面版正面竞争

**描述**：大厂可能跟进做"AI 文件助手"功能，吞掉细分市场。

**缓解**：
- 速度优先：抢 6-12 个月的窗口期
- 隐私故事讲深（大厂结构性做不到）
- 用户社区建立粘性

**应急**：转向更细分的人群（学生 / 创作者垂直版）。

## 技术风险

### T-01 🔴 Tauri 双端兼容性 ≠ 预期

**描述**：Mac WebView (WKWebView) 在某些 UI 特性上和 Win (WebView2) 表现差异大。

**缓解**：
- M0 第 1 周必须做完整双端 PoC
- CI 早期接入 macOS runner
- 避开 bleeding edge CSS

**应急**：
- 选项 A：MVP 只做 Windows（已是计划），Mac 推迟
- 选项 B：迁移到 Electron（包大代价）

### T-02 🔴 缓存命中率上不去

**描述**：实际命中率低于 70%，单用户成本翻倍。

**指标**：< 60% 立即报警。

**缓解**：
- System prompt 设计阶段就有严格规范
- 每次 prompt 改动都跑回归测试
- 自动化测试验证缓存命中率

**应急**：
- 大幅压缩 system prompt（牺牲一些能力）
- 涨价或紧 L1 配额
- 上游 API 涨价时切换供应商

### T-03 🟡 Python sidecar 打包问题

**描述**：PyInstaller 在 Mac 上签名 / 公证问题；Windows 上被杀软误报。

**缓解**：
- M0 就跑通完整签名公证流程
- Windows 提前买代码签名证书
- 用 onedir 模式（比 onefile 友好）

**应急**：
- 评估 Nuitka 替代 PyInstaller
- 极端情况：把 Python 移出，全部 Rust 重写（成本高）

### T-04 🟡 Ollama 本地推理在低配电脑上太慢

**描述**：8GB 内存 + 集显 电脑跑 Qwen3-4B 卡顿，用户体验差。

**指标**：响应延迟 > 10s 即不可用。

**缓解**：
- 提供 1.7B 兜底模型（更小、更快）
- 路由器把简单任务尽量给本地
- 性能监控 + 自动建议用户切到云端

**应急**：在硬件检测时引导这类用户主用云端模式。

### T-05 🟡 Agent Loop 失控（无限循环 / token 爆炸）

**描述**：模型规划出错，反复调用工具，吞 token 也吞用户耐心。

**缓解**：
- 单任务最多 5/20 步硬限（按 tier）
- 单任务 token 上限
- 超时熔断
- 步骤重复检测

**应急**：任务进度长时间无变化 → 自动中断 + 提示用户。

## 模型与供应商风险

### M-01 🔴 DeepSeek / 火山方舟 涨价

**描述**：当前 V4 Pro 已是"原价 1/4"，未来可能反弹。

**缓解**：
- 多供应商架构（火山/DeepSeek/阿里）
- 监控价格变化，每月对比
- 缓存策略让小幅涨价不致命

**应急**：切换主供应商；极端情况调整 L1 配额或 L2 价格。

### M-02 🟡 模型质量倒退或下线

**描述**：某次模型迭代质量下降；某模型被下线。

**缓解**：
- 模型版本固定（不用 -latest）
- 升级前回归测试
- 多供应商兜底

**应急**：迅速切换备用模型 + 公告。

### M-03 🟡 国产模型在英文/编程场景能力不足

**描述**：用户的英文文档处理、代码生成场景下，DeepSeek 不如 Claude/GPT。

**缓解**：
- MVP 不重度依赖英文/编程场景
- L3 BYOK 模式让重度用户自接 Claude/GPT

**应急**：考虑 L2 高级版接入境外模型（合规风险评估）。

## 合规与法律风险

### L-01 🔴 AIGC 备案要求

**描述**：国内监管要求 AI 应用备案，未备案上架被下架。

**缓解**：
- 提前研究备案要求
- 选用已备案模型（DeepSeek / 豆包都有备案）
- L1/L2 数据不出境

**应急**：如必要，做企业版（备案主体明确）。

### L-02 🟡 用户隐私事故

**描述**：bug 导致用户数据意外上报 / 泄露。

**缓解**：
- 数据流走向严格代码审查
- 日志默认不含内容
- 用户可关上报
- 上报数据有完整字段清单可查

**应急**：发现后 24 小时内修复 + 公开说明。

### L-03 🟡 AI 生成内容版权纠纷

**描述**：用户用 AI 生成内容，遇到版权诉讼。

**缓解**：
- 用户协议明确"AI 生成内容由用户自行使用"
- 不主动训练用户数据
- 生成产物可选加水印

## 商业风险

### B-01 🟡 微信/支付宝商户号申请失败

**描述**：个人开发者难以申请商户号（要营业执照）。

**缓解**：
- M0 就开始注册公司（个体户也行）
- 备选方案：用平台（如知识星球、爱发电）

### B-02 🟢 退款套利

**描述**：用户买 L3 买断后退款，或 L2 试用后退款。

**缓解**：
- L2 试用一次性（一个账号一次）
- L3 退款窗口 7 天 + 人工审核
- 设备指纹防止重复

## 团队风险

### T-01 🟡 单点人员风险

**描述**：核心开发者离开 / 生病。

**缓解**：
- 文档体系（这套 SDD 就是缓解）
- 关键决策走 ADR 留档
- 代码 review 制度

### T-02 🟡 进度延期

**描述**：M1-M4 各阶段普遍延期。

**缓解**：
- 每个 Sprint 设最小可行交付
- 范围而非时间灵活（P0 不动，P1 可砍）
- 周回顾

## 评审节奏
