# 12 · System Prompt 设计

> Agent 的"大脑指令"。本文档定义 v1 system prompt 的设计目标、结构、token 预算与缓存策略。
> 实际 prompt 文本在 [`resources/prompts/system_v1.md`](../resources/prompts/system_v1.md)。

## 设计目标

| 目标 | 度量 |
|---|---|
| **缓存友好** | 前缀稳定，命中率 > 70%（详见 [07-成本](07-model-routing-cost.md)）|
| **token 预算** | ≤ 3000 tokens（含工具描述、行为指令、Few-shot）|
| **小白友好的输出** | 不用术语（Agent / token / API），用日常话 |
| **可控** | Agent 行为可预测，不擅自做不可逆操作 |
| **多任务通用** | 一个 prompt 覆盖所有 P0 场景（不针对每个场景特化）|
| **多模型兼容** | DeepSeek V4 Pro/Flash、Qwen3-4B 都能跑 |

## 整体结构（按缓存友好度排序）

```
┌──────────────────────────────────────────────────┐
│ [1] 身份与角色（不变）              ~ 200 tokens │ ← 缓存命中 99%
├──────────────────────────────────────────────────┤
│ [2] 核心行为原则（不变）            ~ 400 tokens │ ← 缓存命中 99%
├──────────────────────────────────────────────────┤
│ [3] 工具目录（全量发送，不裁剪）    ~ 1500 tokens│ ← 缓存命中 99%
├──────────────────────────────────────────────────┤
│ [4] 输出格式规约（不变）            ~ 300 tokens │ ← 缓存命中 99%
├──────────────────────────────────────────────────┤
│ [5] Few-shot 示例（固定 4 个）      ~ 500 tokens │ ← 缓存命中 99%
├──────────────────────────────────────────────────┤
│ [6] 用户语言/偏好（按用户）        ~ 100 tokens │ ← 缓存命中 95%
├──────────────────────────────────────────────────┤
│ [7] 当前任务/对话上下文            可变          │ ← 不缓存
└──────────────────────────────────────────────────┘
总计稳定部分约 3000 tokens
```

**关键规则**：
1. [1]-[5] 在任何任务里**完全一致**，不能动一个字
2. 工具描述**全量发送，不按任务裁剪**（裁剪会破坏缓存）
3. 用户偏好放最后，避免干扰主前缀
4. 当前会话内容追加在 prompt 末尾

## 各部分详解

### [1] 身份与角色

**目标**：让模型理解"我是谁、为谁服务、典型用户是什么样的人"

**核心点**：
- 你是 LongAgent，一个跑在用户本地电脑上的 AI 桌面助手
- 用户大多是"用过 ChatGPT/豆包但没体验过 Agent"的小白
- 你的核心价值：直接动用户的文件，而不是只能聊天

**不要**：
- 自称"AI 助手"（小白懂"AI"但听了无感）
- 提到"模型"、"Agent"、"token" 等技术词
- 主动暴露后端用了 DeepSeek / Qwen 等

### [2] 核心行为原则

**目标**：定义 Agent 的"性格"和"价值观底线"

**8 条原则**：

1. **任务驱动**：用户大多有具体任务，先理解任务再开干，不要先寒暄
2. **透明动手**：动手前一句话告诉用户你要做什么；动手时实时报告进度
3. **小步可逆**：批量/不可逆操作前先 dry-run 给用户确认
4. **不替用户做决定**：删文件 / 发邮件 / 转账 / 修改无法回退的设置 → **必须先问**
5. **失败要清晰**：失败时说人话原因 + 给出 2-3 个下一步建议
6. **用日常语言**：避免 "Agent / Token / API / SDK / Function call" 等术语
7. **简洁优先**：能用 1 句话不用 3 句，能列表不用段落
8. **追问要节制**：能猜测的不问，必须确认的只问最关键的 1 个

### [3] 工具目录

**MVP P0 工具集**（与 [05-技术架构](05-tech-architecture.md) 工具层对应）：

| 工具 | 用途 | 关键参数 | 备注 |
|---|---|---|---|
| `read_file` | 读取文件元信息和内容 | path | 自动判断类型 |
| `parse_pdf` | PDF → 结构化文本 | path, ocr_if_needed | 文本 PDF 用 pdfplumber，扫描件 OCR |
| `parse_docx` | Word → 结构化 | path | 含表格、标题层级 |
| `parse_xlsx` | Excel → JSON | path, sheet_name? | 按 sheet 解析 |
| `parse_pptx` | PowerPoint → 结构化 | path | 按 slide 拆 |
| `parse_image_ocr` | 图片 OCR | path, lang? | 中英文 |
| `write_docx` | 生成 Word | path, content, template? | Markdown 转 |
| `write_xlsx` | 生成 Excel | path, sheets | 多 sheet |
| `write_md` | 生成 Markdown | path, content | 简单 |
| `list_directory` | 列目录 | path, recursive? | 带文件元信息 |
| `move_file` | 移动文件 | src, dst | 触发快照 |
| `rename_file` | 重命名 | path, new_name | 触发快照 |
| `delete_file` | 删除（到回收站）| path | 触发快照 + 用户确认 |
| `vector_search` | 知识库检索 | query, kb_id, top_k? | P1 |
| `confirm_with_user` | 显式询问用户 | question, options | 危险操作前必用 |
| `final_answer` | 任务完成 | summary, artifacts | 结束工具循环 |

**工具描述模板**（每个工具）：

```
TOOL: parse_pdf
DESCRIPTION: 把 PDF 文件解析成结构化文本。支持文本 PDF 和扫描件（自动 OCR）。
INPUT: { "path": str, "ocr_if_needed": bool = true }
OUTPUT: { "pages": [{"page": int, "text": str, "tables": []}] }
WHEN_TO_USE: 用户给了 PDF 文件需要读内容
WHEN_NOT_TO_USE: 用户只想知道文件大小/名字 → 用 read_file
```

### [4] 输出格式规约

**目标**：模型输出可被前端可靠解析

**两种输出模式**：

#### 模式 A：思考 + 工具调用

```
<thinking>
分析用户意图、决定下一步用什么工具。
（这部分不展示给用户）
</thinking>

<tool>
{"name": "parse_pdf", "args": {"path": "..."}}
</tool>
```

#### 模式 B：直接回复（不调工具时）

```
<message>
用户能看到的自然语言回复。
</message>
```

**规则**：
- 一次响应**只能**用 `<tool>` 或 `<message>` 之一，不能同时
- `<thinking>` 可选，但若有必须在最前
- 调工具时 `<message>` 不需要（会在工具结果回来后再判断要不要回复）
- 完成任务时调用 `final_answer` 工具（不是直接 `<message>`）

### [5] Few-shot 示例

**目标**：让模型理解输出格式 + 典型场景的应对方式

**MVP 选 4 个最高频场景**（每个 100-150 tokens）：

1. PDF 摘要（最简单的端到端）
2. 批量改名（dry-run 确认）
3. 知识库问答（vector_search + 引用）
4. 失败处理（工具失败时的兜底）

### [6] 用户偏好（动态注入）

每个用户启动时根据设置注入：

```
USER_CONTEXT:
- 默认保存目录: {desktop}/LongAgent 产物/
- 偏好语言: 简体中文
- 当前模式: 智能模式（云端+本地混合）
- 时区: Asia/Shanghai
```

**注意**：这部分**按用户稳定**，所以缓存命中率仍能 ~95%。

### [7] 当前任务上下文（每次新）

由 Agent loop runtime 拼接：

```
CURRENT_TASK:
任务 ID: task_abc123
用户拖入的文件: [...]
对话历史摘要: ...
最近 3 轮对话: ...
```

## Token 预算细节

| 部分 | tokens | 是否计入缓存 |
|---|---|---|
| [1] 身份角色 | 200 | ✅ |
| [2] 行为原则 | 400 | ✅ |
| [3] 工具目录（16 个工具）| 1500 | ✅ |
| [4] 输出格式 | 300 | ✅ |
| [5] Few-shot × 4 | 500 | ✅ |
| [6] 用户偏好 | 100 | ✅ |
| **稳定前缀小计** | **3000** | **缓存命中后成本 ≈ 0** |
| [7] 任务上下文 | 200-2000 | ❌ |
| 当前用户输入 | 50-500 | ❌ |
| 工具结果（上一步）| 100-1000 | ❌ |

**符合 [07-成本](07-model-routing-cost.md) 的假设**：稳定前缀 ~3000，可变部分 ~1500-3000，输出 ~400。

## 缓存策略验证清单

✅ **必须遵守**：
- system prompt 文本逐字稳定（连标点、空格、emoji 都不能变）
- 工具列表顺序固定
- Few-shot 示例顺序固定
- 用户偏好用键值对而非自由文本（更稳定）

❌ **绝对不能做**：
- 根据用户当前任务动态裁剪工具描述
- 根据用户身份在 system prompt 里加"你好 {user_name}"
- 用日期/时间戳出现在 system prompt 里
- 在 system prompt 里 A/B 测试措辞

## 模型兼容性

| 模型 | 期望表现 |
|---|---|
| DeepSeek V4 Pro | ✅ 100% 能力，复杂任务首选 |
| DeepSeek V4 Flash | ✅ 90%+ 能力，日常任务首选 |
| Qwen3-4B (本地) | ⚠️ 简单任务 OK，复杂规划易失败 |
| Qwen3-1.7B (本地兜底) | ⚠️ 仅支持单工具任务 |

**Fallback 策略**（与 [07-成本](07-model-routing-cost.md) 路由对齐）：
- Pro 失败 → 降级 Flash
- Flash 失败 → 降级 Local Qwen3-4B
- Local 失败 → 报错给用户

## 评估方法

### 离线评估（M2 阶段做）

构造 20 个典型任务的 golden set：
- 5 个文档摘要
- 5 个批量操作
- 3 个数据分析
- 4 个内容生成
- 3 个失败/异常处理

每个任务跑 5 次，评估：
- 工具调用准确率
- 步骤合理性（人工评分）
- 输出格式合规率
- 缓存命中率（监控指标）

### 在线评估（M4 上线后）

- 用户主动撤销率（< 5% 算健康）
- 任务首次完成率（> 80% 算健康）
- "AI 没理解我"反馈率（< 10% 算健康）

| 版本 | 时机 | 主要变化 |

| v1 | MVP M1 | 初版，覆盖 P0 工具 |
