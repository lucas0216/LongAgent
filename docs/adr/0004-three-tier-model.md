# ADR-0004 · 三层用户模型（L1 免费 / L2 订阅 / L3 BYOK）

**状态**：✅ Accepted
**日期**：2026-05-27
**决策者**：产品负责人

## 背景

商业模式选择。候选：

1. **纯 BYOK**（如 Cherry Studio）：用户自配 API Key，App 免费
2. **纯订阅**（如 ChatGPT Plus）：App 帮你管 Key，月费包干
3. **纯买断**：一次性付费下载，可选 BYOK
4. **三层渐进**：免费 + 订阅 + BYOK 三选一

## 决策

**采用三层渐进模型**：
- L1：免费（本地无限 + 云端少量赠送）
- L2：¥29/月订阅（无限云端）
- L3：¥299 一次性买断 + BYOK

## 理由

### 与目标用户匹配

| 用户层 | 当前 AI 习惯 | 适合方案 |
|---|---|---|
| 小白 | 用免费 AI（豆包/元宝）| **L1**（零门槛进入）|
| 重度使用 | 习惯订阅（视频会员）| **L2** |
| 技术极客 | 用 BYOK（Cherry Studio）| **L3** |

**纯 BYOK 在小白这层结构性失败**：onboarding 流程实测转化率 < 20%（详见对话日志）。

### 单一商业模式无法同时满足三种用户

- 纯 BYOK：失去 80% 小白
- 纯订阅：失去懂技术的高频用户（他们觉得"自己有 Key 为什么要再付费"）
- 纯买断：没有可持续收入支持云端成本

### 互相导流

```
小白下载 (L1)
    ↓ 用爽了想要更多
L2 订阅（变现主力）
    ↓ 学了点东西觉得订阅不灵活
L3 BYOK（留住高级用户）
```

L1 → L2 转化是主要收入来源。L3 防止流失到 Cherry Studio。

### 成本结构友好

- L1 单用户成本 ¥0.67/月，5% 转 L2 即可覆盖（详见 [07-成本](../07-model-routing-cost.md)）
- L2 ARPU ¥25/月
- L3 零变动成本（用户自付）

## 设计要点

### L1 的设计目标：让用户感受到 Aha Moment

- **不限制本地能力**（关键差异化）
- **赠送少量云端**（让用户体验云端聪明的瞬间）
- **不要做得太爽**（否则不会升级）
- **明确的升级路径**（配额耗尽时温和提示，不阻塞）

### L2 的设计目标：让付费用户觉得"值"

- 无限云端调用（公平使用政策避免滥用）
- Pro 模型优先（速度感知更聪明）
- 知识库 / 定时任务等高级功能
- 7 天免费试用（一次性）

### L3 的设计目标：留住技术用户、零变动成本

- **隐藏在二级菜单**（小白看不到这个选项）
- 完全自由（任何 Provider、任何模型）
- 一次性付费，无心理负担
- 不抽通道费（生意上诚实）

## 关键参数

| 参数 | 值 | 备注 |
|---|---|---|
| L1 每日云端额度 | 20 次 | 后续按数据微调 |
| L1 单任务调用上限 | 5 次 | 防 token 爆炸 |
| L2 月费 | ¥29 | 比 ChatGPT Plus ¥140 便宜 |
| L2 年费 | ¥299 | ≈ ¥24.9/月，15% 折扣 |
| L2 试用 | 7 天 | 一个账号一次 |
| L3 买断价 | ¥299 | 一次性 |
| L3 设备绑定 | 3 台 | 防滥用 |

## 不选其他方案的理由

### 不选纯 BYOK

- 小白 onboarding 转化 < 20%（详见对话）
- 与"目标用户：小白"根本冲突

### 不选纯订阅

- L1 免费是吸引下载的关键
- 极客用户拒绝"被绑定"，会跑去 Cherry Studio

### 不选纯买断

- 没有持续收入支持云端
- 无法兼顾免费用户体验

### 不选代付（用户在 App 内充值，我们代调 API）

- 法律上变成"AI 服务提供商"，合规要求高
- 退款、对账、客诉成本高
- 与"L1 免费 + L3 BYOK"组合相比无优势

## 后果

### 正面

- 覆盖 90%+ 用户人群
- 互相导流，留存高
- 商业模式可持续

### 负面

- 三套用户系统增加复杂度
- 配额管理、计费、订阅各一套
- 不同 tier 的体验需要精细打磨

## 待验证假设

- [ ] L1 → L2 转化率 > 3%（行业平均）
- [ ] L3 买断用户占比 < 15%（小白主，极客次要）
- [ ] L2 留存月度 > 60%
- [ ] L2 NPS > 40
