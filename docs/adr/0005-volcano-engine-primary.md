# ADR-0005 · 云端模型主供应商：火山方舟，备用 DeepSeek 官方

**状态**：✅ Accepted
**日期**：2026-05-27
**决策者**：产品负责人

## 背景

L1/L2 用户的云端模型从哪里来？候选：

1. **DeepSeek 官方 API**
2. **火山方舟**（字节，DeepSeek 第三方托管 + 字节自家豆包）
3. **阿里云百炼**（DeepSeek 托管 + 通义）
4. **硅基流动**（多模型聚合）
5. **OpenRouter** 等海外聚合（不合规）

## 决策

**主：火山方舟 / 备：DeepSeek 官方 / 兜底：阿里云百炼**

## 理由

### 价格相同时，火山方舟体验最佳

主流国内平台都把 DeepSeek V4 价格与官方对齐：
- 输入缓存命中：¥0.025/M
- 输入缓存未命中：¥3/M
- 输出：¥6/M

差异在**响应速度、稳定性、赠送、合规背书**：

| 平台 | 价格 | 速率/准确率 | 赠送 | 备注 |
|---|---|---|---|---|
| DeepSeek 官方 | 基准 | 最稳 | 无 | 个人开发者好 |
| **火山方舟** | 同价 | **几乎=官方** | **有活动** | 字节背书 |
| 阿里云百炼 | 同价 | 较稳 | 偶有 | 阿里背书 |
| 硅基流动 | 同价 | Pro 限速 | 14 元（仅非 Pro）| 调试用 |
| OpenRouter | **贵 2-3 倍** | 一般 | 无 | 不考虑 |

### 火山方舟的独特优势

- 字节背书 → 企业资质对未来融资 / 上市 / 合规有利
- 多模型聚合 → 也可调豆包等字节模型（备用）
- 国内首选企业级 LLM 平台

### 多供应商兜底是必须的

任何单一供应商都有故障 / 限流风险。架构必须支持：

```
请求 → 主（火山）→ 失败/限流 → 备（DeepSeek 官方）→ 失败 → 兜底（阿里）→ 失败 → 本地降级
```

实测：海外供应商（OpenRouter / Together）单价高 2-3 倍，且涉及数据出境合规，**禁用**。

## 计费模式

**MVP 阶段**：
- L1/L2 用户的调用通过**我们的后端代理**转发到火山/DeepSeek
- 这样我们可以：
  - 集中管理 API Key（不暴露给客户端）
  - 统计成本、检测滥用
  - A/B 测试不同供应商
  - 应急切换不需要客户端发版

**L3 BYOK 阶段**：
- 用户自己的 Key，**客户端直连各家 API**
- 我们不经手 token，零变动成本

## 实现要点

### 抽象层

所有云端 Provider 通过统一接口（OpenAI 兼容协议）：

```python
class LLMProvider:
    async def chat(self, messages, model, ...) -> Response: ...
    async def health_check(self) -> bool: ...
    def estimated_cost(self, response) -> float: ...
```

实现类：
- `VolcanoEngineProvider`
- `DeepseekOfficialProvider`
- `AliyunProvider`
- `OpenAICompatibleProvider`（L3 用）

### 健康度监控

```python
# 每分钟检查
for provider in [volcano, deepseek, aliyun]:
    provider.health = await provider.health_check()

# 路由时选择最优健康
def pick_provider():
    healthy = [p for p in providers if p.health]
    return healthy[0]  # 按优先级
```

### 缓存策略

DeepSeek 的缓存机制是**按服务方独立的**——同一个 prompt 发给火山和发给官方，缓存命中是分开的。

**结论**：尽量保持流量集中在一个供应商上，缓存命中率才高。**主供应商不要轻易切换**。

## 关键参数

| 参数 | 值 |
|---|---|
| 主供应商 | 火山方舟 |
| 主健康度阈值 | 95% 成功率（5 分钟窗口）|
| 切换备用条件 | 连续 5 个请求失败或限流 |
| 主供应商恢复条件 | 切回备 10 分钟后健康度 > 99% |
| 客户端超时 | 30s（任务级）|
| 重试次数 | 2 次（指数退避）|

## 风险

### R-1：DeepSeek V4 涨价

当前 ¥0.025/M（缓存命中）是"原价 1/4"，2026/5/31 后变成永久价。**短期不会涨**。

长期监控，准备：
- 切换至豆包 / 通义（如更便宜）
- 调整 L1 配额
- 调整 L2 价格

### R-2：火山方舟限流

字节高峰期可能限流。备用 DeepSeek 官方 + 阿里云百炼。

### R-3：模型下线

DeepSeek 突然下线 V4 不太可能（其商业根基），但仍需准备：
- 兼容 V5 / Flash 升级版的接入
- 应急切换至豆包 Pro / 通义 Plus

## 不选其他方案的理由

### 不选 DeepSeek 官方作为主供应商

- 速度/稳定性几乎一样，但火山有字节企业背书
- 火山有赠送活动
- 官方更适合个人开发者，企业级用火山

### 不选海外聚合（OpenRouter 等）

- 价格贵 2-3 倍
- 数据出境合规问题
- 国内访问速度问题

### 不选直接接入 Claude / GPT-4

- 国内合规问题
- 价格贵 5-10 倍
- 中文场景不一定优于 DeepSeek V4

### 不选完全本地

- 本地能力天花板低，复杂任务体验差
- 用户付了订阅费希望体验更聪明的 AI

## 后果

### 正面

- 成本可控
- 国内合规
- 字节背书利好后续融资

### 负面

- 与字节生态绑定（长期看是双刃剑）
- 多供应商架构复杂度
